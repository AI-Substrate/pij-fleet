## Source attribution and regression assessment

Source at the reported deployed revision confirms:

- **s07:** holdings/memory-turn handling is entered from compact or close. A held action has one live event subscription/deadline, not a periodic fleet sweep. There is no new steady-state worker for each of the 102 seats.
- **s11:** deliveries are read by **single-seat POST /v1/state only**, not bulk `/v1/cards`; claim/claim-list/delivered are explicit commands. Claim release piggybacks an actual tombstone transaction. Startup adds gh resolution and memory-turn configuration, not a new TickLoop.
- Existing clients polling `/v1/state` still pay its new indexed delivery read per call; ordinary projection/serialization and active memory turns can consume CPU. No HTTP request-rate or stack evidence was collected to assign this CPU.
- This deployed tree **still contains the original per-observation registration ps producer and `/bin/date` offset producer**. The #134 in-process offset/cached host-reader change is not in this reported deployment. Date has several callers, including the old conditional pending-Claude binder path; +26 cannot identify which caller ran.
