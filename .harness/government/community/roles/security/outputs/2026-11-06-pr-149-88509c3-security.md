## S001: argv-safe names are not tmux-format-safe

[Release rename:786-789](https://github.com/AI-Substrate/pij-fleet/blob/88509c3a80e6fa919ee3c5c75f0804e5d4402d67/crates/daemon/src/community/directory.rs#L786-L789) selects a next holding and constructs its name from the raw instance at lines 1251-1256. [Holding parsing:969-979](https://github.com/AI-Substrate/pij-fleet/blob/88509c3a80e6fa919ee3c5c75f0804e5d4402d67/crates/daemon/src/http/directory.rs#L969-L979) rejects slash/surrounding whitespace, not format syntax; holders schema instance is an unrestricted string.

[rename_window:1486-1492](https://github.com/AI-Substrate/pij-fleet/blob/88509c3a80e6fa919ee3c5c75f0804e5d4402d67/crates/tmux/src/lib.rs#L1486-L1492) correctly uses fixed argv and --. That prevents option/shell parsing problems at process launch, not interpretation by tmux.

In authoritative [tmux 3.6a rename-window source](https://github.com/tmux/tmux/blob/3.6a/cmd-rename-window.c), the name passes through format_single_from_target. [Default expansion:5693-5736](https://github.com/tmux/tmux/blob/3.6a/format.c#L5693-L5736) enables the path where [command-substitution formats:5553-5574](https://github.com/tmux/tmux/blob/3.6a/format.c#L5553-L5574) reach [job_run:410-413](https://github.com/tmux/tmux/blob/3.6a/format.c#L410-L413). An imported hostile instance can therefore launch a shell job when selected for the window name.

This sink is version-dependent; 3.6a behavior was source-verified, not asserted for every tmux version or independently attested on the deployed host. No payload was run. Repair the shared rename boundary for literal interpretation across supported versions, covering assign and release. Shell quoting alone does not close this engine-level sink.

## S002: refusal command includes raw shell syntax

[Several-holder refusal:351-354](https://github.com/AI-Substrate/pij-fleet/blob/88509c3a80e6fa919ee3c5c75f0804e5d4402d67/crates/daemon/src/delivery/role_send.rs#L351-L354) inserts row.instance directly into its runnable pij send recommendation. The same accepted holding data can contain substitutions/metacharacters. A human or agent following that command executes shell syntax before pij's stricter address validation. Viewing the refusal alone does not execute it.

Use the existing core::directory::shell_word helper on complete dynamic arguments, consistently including target addresses, seats and projects. Importing data does not authorize its execution. Add hostile-instance coverage at both the guidance and native rename boundaries.

## Other reviewed boundaries

Withdrawal resolves the caller, loads the stored request and checks its stored requester/project before mutation. The withdraw leaf accepts why, not caller-supplied actor/project authority. Scope/authority reads propagate errors rather than selecting privileged fallback. Documented authority includes project PA/prime, current machine designation and prime-role seats, not project-prime-only isolation.

List responses explicitly omit bodies and bind project/role/state with a 100-row cap. Internal rows can contain bodies, but those are not serialized. Explicit project selection follows existing trusted-local directory semantics, not per-project membership authorization.

Closing transactionally moves only queued requests; current-holder claim logic protects delivery races. Authority reads are outside that transaction, so universal atomic revocation is not claimed. Replay/self-close/drain identity and mandatory cold audit remain. Peer keys cannot use the route; existing shared-local-bearer/paneless assertion limits remain.
