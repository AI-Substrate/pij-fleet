## Explicit consistency and granularity limits

FYIs are per non-self withdrawn request, not grouped per requester: http/directory.rs:828 creates request-id.withdrawn identities. Several requests from one requester can yield several FYIs. Self-requesters receive told:self. This qualifies the packet's one-per-requester wording and is also recorded by performance.

The Git retirement commit precedes withdrawal, then pointer recording and FYIs. Only the DB deletion/event pair is atomic, not Git plus DB plus notification. Withdrawal failure names the landed commit. Crash/cancellation or later pointer failure can leave completed withdrawal without notification. An already-started producer inserting afterward, or a delivering claim later released, can leave a queued request behind. These are consistency/reliability limitations, not demonstrated unauthorized access or disclosure.
