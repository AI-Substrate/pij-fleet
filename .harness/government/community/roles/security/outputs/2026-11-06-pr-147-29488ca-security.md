## Binary resolution: PATH is the trust boundary

The fast path invokes bare pij-rs through PATH, not an absolute pinned binary. There is no fast-path PIJ_RS_BIN override, canonicalization, ownership/version/authenticity check or application-level symlink/executable validation. Relative and empty PATH components are not filtered.

An attacker-controlled PATH entry can therefore win executable selection, including a CWD/repository-relative executable or symlink. A successfully launched wrong binary is not detected. Operators must trust the inherited PATH and its writable directories.

No default lower-trust executable location or attack independent of trusted caller execution/environment control was established. The prior native launcher also used bare pij-rs, although previously HTTP-routed community calls acquire this executable-selection dependency through the new fast path.

This is not equivalent to the stricter ddocs-check resolver at harness/scripts/ddocs-check.ts:23-43, which rejects relative pins and skips relative PATH components. Ordinary PATH semantics are also intentional in crates/core/src/program.rs:145-163. The status-line PIJ_RS_BIN variable is locally assigned discovery data, not a shim override contract.
