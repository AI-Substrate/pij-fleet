## S001: accepted assignment data becomes executable command text

A batch assignment can contain the literal data `qa/x$(id) pij-holder`. These are illustrative fixture values, not a command to run. Preconditions are an active qa role able to accept the holding and an existing live holder seat.

http/directory.rs:1144-1169 splits the row into two fields and invokes role_and_instance. Its checks at 1109-1119 restrict the role, but reject instances only for slash or surrounding whitespace. The literal instance x$(id) passes; the stricter role-send instance grammar is not applied.

There is no later exclusion of substitution syntax: .dd/schemas/pij/holders/schema.json:52-54 defines instance_key as string; community/holders.rs:32-59 checks closure/duplicates rather than instance characters; :253-282 serializes it unchanged; migration 0032_community_assignments.sql:11 stores unrestricted TEXT with bound SQL parameters.

A subsequent retirement refusal interpolates the stored instance into this recommendation shape:

```text
pij directory release qa/x$(id) pij-holder --why <text> --project demo
```

This is the vulnerable emitted text, not an instruction to execute it. After replacing the ordinary reason placeholder, following the recommendation performs command substitution in the operator's shell before pij can validate argv. cli/src/lib.rs:53-58 does not escape that rendering.

The boundary is data authoring versus command execution: a contributor can supply a batch file that an authorized operator imports as assignment data. The contributor need not possess the operator's bearer credential. A later recommended command promotes that independently authored data into shell syntax. Trusted-machine API authority does not make all imported data shell-safe.

This is a static admission/schema/persistence/render trace, not an executed payload or unauthenticated daemon-access claim. No local recommendation, script or probe was executed.

### Required repair

Use the existing pij_core::directory::shell_word helper on complete dynamic command arguments, particularly the combined role/instance target, seat and project. Do not rely on role-send grammar to validate holding instances. Preserve the supported data rather than relying on a narrow shell-character denylist.

Add a hostile-instance word-round-trip regression that fails the current emitter. The current replay test splits whitespace and uses simple names, so it does not prove shell quoting. Tests must not invoke the recommended role-mutating operation.
