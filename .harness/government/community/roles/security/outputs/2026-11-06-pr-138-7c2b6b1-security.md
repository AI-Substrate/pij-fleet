## F18: writer marker is advisory, not lock ownership

[writer.rs:236-280](https://github.com/AI-Substrate/pij-fleet/blob/7c2b6b147d158746545699226343a3fd09b7bdeb/crates/daemon/src/community/writer.rs#L236-L280) creates pij-writer.owner before staging, including while waiting for somebody else's index.lock. It identifies a writer attempting work, not necessarily the lock owner.

[Marker implementation:392-443](https://github.com/AI-Substrate/pij-fleet/blob/7c2b6b147d158746545699226343a3fd09b7bdeb/crates/daemon/src/community/writer.rs#L392-L443) is best-effort filesystem metadata. Anyone with write access to that Git directory can forge or replace it. Normal scope exit removes it; crash/SIGKILL can leave a stale marker, and a later write overwrites it. No operation uses it to authorize writes or delete a foreign lock. It must not be treated as ownership attestation or permission to clear locks.

[Seat selection:161-178](https://github.com/AI-Substrate/pij-fleet/blob/7c2b6b147d158746545699226343a3fd09b7bdeb/harness/scripts/shared-build.sh#L161-L178) uses the documented environment/whoami/user fallback. The owner-seat label is diagnostic, not authentication.
