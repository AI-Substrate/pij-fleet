## S001: failed scope lookup permits broader fallback

[held_projects and queued_requests:1046-1139](https://github.com/AI-Substrate/pij-fleet/blob/464e06127edccf4356085c6e19075f52e292eef9/crates/daemon/src/pa_watchdog.rs#L1046-L1139) silently convert open_assignments errors into empty vectors with unwrap_or_default. The only two callers are the PA-scope lookup and, if it appears empty, the parent-scope lookup. An unknown scope can therefore be treated as successful emptiness and select a broader scope.

If a PA actually holds project A but its read fails, a successful parent read for project B selects B even though A should have taken precedence. If the required parent read fails or appears empty and the parent is the current designated prime, successful later reads can select all projects, including unrelated C. A successful empty own/parent result remains a legitimate fallback and is not itself a finding.

[Store projection:274-324](https://github.com/AI-Substrate/pij-fleet/blob/464e06127edccf4356085c6e19075f52e292eef9/crates/store/src/role_requests.rs#L274-L324) treats None as the unfiltered queued scope and retains all delivering metadata; concrete scopes bind projects and filter results. Both [idle-edge and prime-active wake paths:487-540](https://github.com/AI-Substrate/pij-fleet/blob/464e06127edccf4356085c6e19075f52e292eef9/crates/daemon/src/pa_watchdog.rs#L487-L540) deliver that digest to the PA without another project check.

Exposed metadata includes project, role/instance, request and requester IDs, waiting duration and delivering-holder IDs. Request bodies remain replaced with empty strings and are not disclosed. This is cross-project context disclosure within the existing trusted-machine model, not remote unauthenticated access or a new mutation capability.

## Preconditions and limits

The scenario requires a selective assignment-read error or transient fault followed by successful later reads and message admission. A persistent whole-database/schema outage is not enough. Missing parent, nonmatching/failed designation and failed unsettled-request query prevent the global path; the final query failure is logged, but earlier assignment failures are swallowed.

No attacker-controlled failure trigger or executed fault simulation is claimed. These are source-proven conditional paths, not a local reproduction. Scope precedence is specified by AC5 and the API consumer documentation.

## Required repair and evidence

Preserve Result from held_projects. If either required assignment lookup fails, log the failure and omit the queue section rather than continuing fallback. Broader fallback must require successful empty reads. Add separate own-read-error and parent-read-error regressions while preserving the successful-empty fallback control.

Existing vector-based digest and successful store-read tests do not exercise read failures. The earlier exact-tree CI success, 2,020 passing cases and latest delivers success remain valid but do not cover S001. No other original security observations are withdrawn; they do not justify approval of this scope-error path.
