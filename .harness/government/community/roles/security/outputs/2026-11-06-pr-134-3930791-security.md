## S001: fail-open cross-PID batch parsing

parse_native_batch accepts every textual u32 PID without a requested-PID set, then inserts records into a HashMap. At 1806 duplicate PIDs silently replace earlier records. BatchedAncestry::observe at 1714-1738 subsequently retrieves those records as the named process's evidence.

The input is not wholly trusted simply because /bin/ps is trusted. The inspected public Darwin ps implementation escapes args with strvis but prints ucomm from p_comm directly. An image filename containing a newline can therefore create additional textual records.

An attacker-controlled descendant can initially have the eligible name node, enter the selected batch, then exec a newline-bearing image before ps. Exec preserves PID and process start identity. A sixteen-character accounting name can split the output into two syntactically valid rows, the second naming an actual selected ancestor PID and supplying a forged node harness/session argv. Under the inspected same-terminal PID ordering, a lower-PID ancestor's genuine row precedes the descendant's injected row and is overwritten.

The normal name/argv/session matchers then evaluate injected text as that ancestor's evidence. Paneless admission at 224-258 can accept the claimed session instead of seeing the real nearest conflicting harness. The existing start-time sandwich does not detect an exec that preserves start identity.

Prerequisites are local machine-bearer access, control over a descendant image/argv, a name-observation/exec timing window, suitable row ordering, and absence of an independent contradictory roster-ownership refusal. This is not arbitrary remote access, a bypass of existing roster checks, or cryptographic per-seat authentication. It is a regression in the process evidence those checks consume: the previous single-process parser rejected multiple rows.

This finding is source-derived, not an executed exploit. Public Apple adv_cmds revision 6bed8737a34dbb54782a18f47dccf933a9967a12 was inspected for raw ucomm, escaped args and default terminal/PID ordering; public XNU fork/exec source was inspected for preserved start time. No correspondence to an inspected local kernel/ps binary is claimed.

Vendor references: [raw ucomm, print.c:415-423](https://github.com/apple-oss-distributions/adv_cmds/blob/6bed8737a34dbb54782a18f47dccf933a9967a12/ps/print.c#L415-L423); [escaped arguments, print.c:306-342](https://github.com/apple-oss-distributions/adv_cmds/blob/6bed8737a34dbb54782a18f47dccf933a9967a12/ps/print.c#L306-L342); [terminal/PID ordering, ps.c:1270-1296](https://github.com/apple-oss-distributions/adv_cmds/blob/6bed8737a34dbb54782a18f47dccf933a9967a12/ps/ps.c#L1270-L1296). [XNU kern_fork.c:1123-1131](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/kern/kern_fork.c#L1123-L1131) preserves p_start during exec; that XNU reference was read on mutable main, not a pinned installed-kernel revision.

## Required repair

Bind parsing to the requested PID set and fail closed on duplicate, unexpected or invalid rows rather than replacing evidence. Remove the raw line-injectable name field from the record protocol, or otherwise make record boundaries unambiguous while preserving the name/argv identity checks. Missing observations for subsequently visited candidates must still refuse.

Add deterministic CI negative cases for duplicate/unrequested IDs and newline-bearing process-name output. The current ordinary mapping, empty-output and nonnumeric-ID cases do not cover this boundary.
