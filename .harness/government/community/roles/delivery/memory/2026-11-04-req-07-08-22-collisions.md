- **tags:** s05, s06, s12, delivery, role-queue, reply-modes, cold-wake, watchdog, fyi
- **hook:** Read before starting s05/s06/s12: the seams, the open rulings, and the cost traps, with file:line anchors at f398ba8.

## Shape of today's path (f398ba8)

- One send path: `http/mod.rs:1689 send` → `cold_wake::guard` → `DeliveryService::accept` → `arrive` (`delivery/mod.rs:983`). Everything after the HTTP handler is keyed on a concrete `SeatId`; the first thing `arrive` does is `registry.get(&to)`.
- `--fyi` branches off before the guard (`http/mod.rs:1748` → `hold_fyi`). Controls branch off too.
- The delivery queue is `jobs` with `kind = 'delivery:<seat>'` and `serial_key = <seat>` (`store/src/queue.rs:130,272`). A job needs a recipient seat at enqueue.
- Daemon-internal sends (`DeliveryService::accept/send`, from `pij-bg`) skip the HTTP cold-wake guard. The PA watchdog audits cold wakes itself (`pa_watchdog.rs:263 audit_cold_wake`, `:320 wake_pa`).
- The 60 s round is `pa_watchdog.rs:384 round`. It runs every tick whether or not a PA exists (`optin_round`, `limit_round` first, then the PA loop). `wake_target` (`:722`) already resolves PA, else designated prime, else lowest `prime`-role seat, per repo scope.
- A card is the latest `report.now` spine event: `spine.latest_matching(seat, &["report.now"])`, one indexed LIMIT 1 read (`pa_watchdog.rs:1042 stale_cards`).
- Latest migration is `0030_limit_wakes.sql`. Any new table needs a number from pm/001.

## req-07 (send to a role, the role queue)

1. **Address grammar.** `parse_destination` (`core/src/address.rs:24`) treats anything before `@` as a seat id, and `SeatId` is an unvalidated string, so `role:pm/021` parses today as a seat and fails `NoRegistryEntry`. Role resolution must sit in front of `arrive`, in the HTTP handler or a resolver the handler calls. Also: reserve the `role:` prefix at registration so no seat can be named `role:x`; and refuse `role:x@machine` by name (n-1, not forwarded).
2. **Three parsers.** Native CLI `pij-rs send --to` (`cli/src/main.rs:344`), shim argv `parse_send` (`http/shim.rs:247`, unknown flags refuse), and the TS `pij_send` tools (`.omp/extensions/pij/index.ts`, `.copilot/extensions/pij/extension.mjs:88`). `--reply` and `--limit` must land in all of them or the shim refuses them. `crates/cli/tests/skill_verb_coverage.rs` and `generation-skill-coverage.test.ts` gate the skill tables.
3. **The queue cannot be a delivery job.** With 0 holders there is no `serial_key`. It needs its own table (requests: role, instance, requester, msg_id, body, reply mode, limit, state). Draining it needs a trigger on **assign** (s04's verb), or queued requests sit forever. That is a cross-step seam s04 has to expose.
4. **Name collision with seat roles.** `RoleService` already has a closed vocabulary `prime | pm | worker | pa` (`seat_roles`, api doc "Seat roles (plan 166)"). PRD core roles are `prime, pm, pa, coder, reviewer`. `role:pa` and `role:pm` must resolve through directory assignment (s04), not `seat_roles`; the two can disagree. Needs a ruling on which wins, or a rule that keeps them in step.
5. **`--fyi` to a role.** An FYI is held per recipient seat (`fyis` table). With 0 holders there is none. Refuse `--fyi` on a role send, or queue it as a request? Unspecified.
6. **Cold-wake with 1 holder.** The guard must run on the resolved holder, and `--force --reason` passes through. A request drained later from the queue goes through internal delivery and skips the guard; a fresh assignee is usually warm, so probably fine, but say so.
7. **"Shows in the PA's watchdog feed."** The digest only goes out at the idle edge or prime-active wake. The queue will show there, but the PA learns of a new queued request from the immediate wake req-07 asks for, not from the feed. "Live holder" needs one definition (not tombstoned and not observed dead, as the death sweep reads it).
8. **The PA wake's "context size of the old seat"** comes from the session facts the cold-wake verdict already reads (`http/cold_wake.rs verdict`), with a 3 s bound. Reuse it; do not add a new read.

## req-08 (reply modes)

1. **Two meanings of FYI.** `--fyi` today is the delivery mode of THIS message. `--reply fyi` is how the requester hears back later. Same word, different flag; the CLI help and refusals must keep them apart.
2. **Linking an output to its request.** The PRD says "the output that answers it" but s06's `pij output --subject` has no request field. We need `--answers <msg_id>` (or `in_reply_to`, which `Msg` already carries) on the output. Without it, notification cannot find the requester. Needs a ruling before s06.
3. **Waking a cold requester.** Notification is daemon-internal, so it skips the guard. `wake` on a cold requester is a priced wake (~$6 on a 700k seat). Options: treat it like the PA watchdog's exemption with a `send.cold-wake-forced` audit (reason e.g. `reply-wake`), or respect the guard and fall back to an FYI. `block` and `failed` "always wake" makes this a real choice. Needs a ruling.
4. **"Nearest seat above"** for an unrequested output: the recorded parent, else the prime via `wake_target`'s ladder. The parent might be tombstoned; then walk up or go to the prime.

## req-22 (time limits)

1. **Where the default lives.** "The role's default limit" has no field in req-04's role definition list. s02's schema needs a `default_limit` field, or s12 has no default to read.
2. **Busy seats cannot be checked in mid-turn.** Copilot and OMP/Pi bodies go over the extension stream and land at the turn boundary; a seat deep in a long turn sees the check-in only when the turn ends (observed repeatedly on Copilot seats). So "does not answer" must be timed from the check-in's **delivery**, not its send, or every long turn becomes a PA notice.
3. **When the clock starts.** For a role-queued request, start at delivery to the holder, not at queue time, or the wait for an assignee counts against the seat.
4. **Card restart.** A card update resets the clock: compare the latest `report.now` `at` with the request's start. One LIMIT 1 read per open limited request per round, as blueprint k-4 says. Keep it inside `round` next to `limit_round`.
5. **Cost trap.** `PaWatchdog::repo` caches only successes; a folder git cannot place launches `git rev-parse` on every call (`pa_watchdog.rs:966`). If s12 or the req-07 wake call `scope_of`/`wake_target` per tick per request, a non-git folder becomes a launch per tick. Record any new launch site with the spawn counter (`crates/testkit/tests/spawn_sites.rs`). Measure with `pij-rs --json ping | jq .data.spawns` and `just spawn-rate --seconds 20` before and after.
6. **Brake or policy.** The check-in is a policy (it decides to send). "Card updated since" is a brake (it can only spare a check-in). Say so in the PR.

## Framing

A delivered role request should tell the holder it was addressed to a role, the request id, the reply mode and the limit. `frame_message` (`core/src/framing.rs`) has golden fixtures; a frame change touches them and the TS `FRAME_RE` (`.omp/extensions/pij/core/message.ts:9`).
