## What those 3452 are: failed PATH-search attempts (evidence/scripts/follow.py, 15 s, 700 followed)
First sight: SRUN, p_flag 0x2006 (P_WEXIT set: already exiting), argv unreadable; all 700 vanished without exec or zombie.
Cause: ProcLiveness runs Command::new("ps") by bare name. Rust spawns it with posix_spawnp, and macOS libc's
posix_spawnp calls posix_spawn once per PATH entry. In XNU each failed attempt creates a process before the image
lookup fails, then tears it down. The daemon's PATH has 32 entries; misses before the hit:
  ps 17 (/bin), date 17 (/bin), lsof 18 (/usr/sbin), git 12 (/opt/homebrew/bin), tmux 12 (/opt/homebrew/bin)
Controlled experiment (evidence/scripts/spawnp_exp.py, the daemon's PATH, 100 spawns each, PIDs consumed from the pid counter):
  posix_spawnp("ps")   -> 1811 PIDs = 18.11 per launch
  posix_spawn("/bin/ps") -> 100 PIDs = 1.00 per launch
So the daemon creates about 18 kernel processes per liveness check: ~6.5/s x 18 = ~118 process creations/s.
(kinfo's 3452/379 = 9.1 per ps is a lower bound: the sampler misses the shortest-lived attempts.)
